HOW TO APPLY THESE FILES ON GITHUB (WEB BROWSER ONLY)
=======================================================

Only 5 files changed this time. Unzip this, then use GitHub's
"Add file -> Upload files" button, dragging in the CONTENTS one
top-level folder at a time (docs, src, tests, website). All 5 files
already exist in your repo, so GitHub will ask "replace existing
file?" for each - say yes.

Folders to drag in, one at a time:
  docs      (1 file)
  src       (1 file, inside src/packing/)
  tests     (1 new file)
  website   (2 files, inside website/css/ and website/js/)

Full file list:

  docs/ageing-and-project-naming-conventions.md
  src/packing/pipeline.py
  tests/test_packing_project_names.py             (NEW)
  website/css/production.css
  website/js/production-table.js

What changed, in short:

1. Project Name consistency between Packing and the other
   dashboards. Packing was parsing its own project name out of each
   workbook's Summary sheet title (e.g. "Vogt Power ( Bison )"),
   independent of the DPR-based name every other dashboard uses
   ("VOGT Bison" for that same project) - two different names for
   one project depending which page you were on. Fixed: the DPR
   (Fabrication workbook) is now the single canonical Project Name
   source everywhere, and it overrides Packing's own parsed name
   wherever the DPR has that project code. The Summary-sheet-parsed
   name only survives as a fallback for a project the DPR doesn't
   have yet.

2. Sorting added to the Production dashboard's Spool List table.
   Click any column header to sort ascending, click again for
   descending, click a third time to go back to unsorted - there's
   a small arrow indicator showing the current sort. Blank/
   unreached values (e.g. a spool that hasn't hit PDQC yet) always
   sort to the bottom so they don't misleadingly rank ahead of real
   numbers. The "Project" column sorts by name (not the raw code),
   matching what's actually shown in that column.

After uploading, run `python3 packing_main.py` once so Packing's
project names actually get corrected - the code change alone won't
fix already-published data until the pipeline re-runs. The
Production sorting change is pure front-end (website/js,
website/css) and works immediately, no pipeline re-run needed.
