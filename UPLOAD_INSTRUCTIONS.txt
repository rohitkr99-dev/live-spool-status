HOW TO APPLY THESE FILES ON GITHUB (WEB BROWSER ONLY)
=======================================================

This zip contains only the files that CHANGED since your last
update (all 16 of them - the Quality dashboard itself is already in
your repo from before, this is fixes + the new Project Name
convention on top of it). Unzip it, then use GitHub's
"Add file -> Upload files" button, dragging in the CONTENTS one
top-level folder at a time (docs, src, tests, website). Every file
in this zip already exists in your repo, so GitHub will ask
"replace existing file?" for all of them - say yes to each.

Folders to drag in, one at a time:
  docs      (new folder - 1 file)
  src       (3 files, inside src/packing/ and src/production/, plus
             src/summary.py directly in src/)
  tests     (1 new file)
  website   (11 files, inside website/css/ and website/js/)

Full file list:

  docs/ageing-and-project-naming-conventions.md   (NEW)
  src/packing/pipeline.py
  src/production/ageing.py
  src/production/summary.py
  src/summary.py
  tests/test_production_stage_display_days.py     (NEW)
  website/css/styles.css
  website/js/packing-charts.js
  website/js/packing-pdfExport.js
  website/js/packing-tables.js
  website/js/production-app.js
  website/js/production-charts.js

  website/js/quality-charts.js
  website/js/tables.js

What changed, in short:

1. Ageing can never go negative - fixed a bug in the Production
   dashboard's spool table where a stage's "days" column could show
   a negative number (e.g. "PDQC (d): -17"). Also documented the
   rule site-wide so it doesn't regress elsewhere - see the new
   docs/ file.

2. Fixed the Quality dashboard's "Rework Rate Over Time" chart not
   responding to the Day/Week/Month dropdown - it was throwing a
   silent error every time you switched it.

3. Project Name now leads everywhere a project is shown (tables,
   chart axes, filters), with the Project Code alongside in
   brackets, smaller where the surface allows it - across the
   Projects, Production, Packing & Dispatch, and Quality dashboards.
   Full reasoning and the (few, deliberate) exceptions are in
   docs/ageing-and-project-naming-conventions.md.

After uploading, run `python3 main.py` (and `python3 production_main.py`
/ `python3 packing_main.py` if you use them) at least once so the
new project_name fields actually populate the dashboards - the code
changes alone won't show new data until the pipelines re-run.
